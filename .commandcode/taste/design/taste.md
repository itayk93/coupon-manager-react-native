# Taste

- Dislikes UI that looks generic or "AI-generated" (template-like): stock icons, blue gradient squares, perfectly symmetric layouts. Prefers screens that look like real, deliberate products — brand-specific, minimal, and purposeful. Confidence: 0.8
- Prefers platform-native UX patterns over custom screens that duplicate OS functionality (e.g., using the OS biometric dialog instead of building a custom "Face ID" screen); when a pre-auth screen exists, it should be minimal and branded. Confidence: 0.7- Prefers currency amounts formatted with a comma thousands separator and the shekel sign (₪) to the LEFT of the number (e.g., ₪1,000.00, ₪10,000.00, ₪1,000,000.00), applied consistently across all wallet/statistics figures. Confidence: 0.8
- Prefers interactive data displays: KPIs should be clickable and open a drill-down modal (years → months), and charts should reveal a tooltip on tap/click. Confidence: 0.6
- Cares about cognitive load / visual density in data-heavy screens: proactively flags a dense list of stat cards as "cognitively overloaded" and treats reducing that overload as a goal to solve, not something to accept. Confidence: 0.5
- Wants the company logo/icon shown wherever the company is identified, not only in list rows — e.g., also in a drill-down bottom-sheet header next to the company name, keeping brand-specific visual identity consistent across views. Confidence: 0.6
- In Hebrew/RTL interfaces, horizontal scrollable rows (chip filters, carousels) should scroll left-to-right with the most important item anchored on the right edge and visible initially, rather than following the default RTL scroll direction. Confidence: 0.7
- Prefers ordering filter/selector chips by data-driven importance (e.g., descending coupon count) so the highest-value option sits at the natural reading start (right side in RTL). Confidence: 0.6
- Cares strongly about typography consistency and wants Heebo to be the sole font across the whole UI (body, headings, and numbers alike) — rejects mixed font stacks like Outfit for h1–h6 or Rubik for large balance digits. Confidence: 0.9
