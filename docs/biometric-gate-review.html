סקירת מסך ה־Biometric Gate

הערכה כנה על המסך שנועל את האפליקציה עם Face ID / Touch ID — והשוואה לאיך שאפליקציות אחרות פותרות את זה.

השורה התחתונה: כן, זה נראה קצת יותר מדי "AI". לא כי זה מכוער — אלא כי הוא עושה עבודה שמערכת ההפעלה כבר עושה, עם מראה תבניתי וסימטרי מדי.

מה בדיוק נראה גנרי

המסך ב־src/components/layout/BiometricGate.tsx מציג:

  • אייקון Face ID בריבוע כחול עם גרדיאנט.
  • כותרת "הארנק נעול" ותת־כותרת "אמת את זהותך עם Face ID כדי להמשיך".
  • כפתור כחול "פתיחה עם Face ID".

התחושה היא של תבנית אונבורדינג: סימטריה מושלמת, אייקון סטוק, וריבוע גרדיאנט כחול. זה עיצוב "נקי" אבל חסר החלטה מוצרית.

מה עושות אפליקציות אחרות

בנקים ומנהלי סיסמאות (Chase, 1Password, Authy וכדומה) לא מציירים מסך Face ID משלהם. הסיבה פשוטה: ב־iOS וב־Android, דיאלוג האימות הביומטרי נשלט על ידי מערכת ההפעלה.

  • אפליקציות קוראות ל־LAContext.evaluatePolicy ב־iOS או ל־BiometricPrompt באנדרואיד, והדיאלוג של אפל/גוגל נפתח מיד.
  • אם יש מסך הכנה, הוא מינימלי: לוגו, טקסט קצר, ולפעמים אין כפתור בכלל — הבקשה רצה אוטומטית.
  • תמיד יש fallback גלוי באותו מסך, כמו כניסה עם סיסמה או PIN.

הבעיה האמיתית בפלואו הנוכחי

הוויזואל הוא רק חצי מהסיפור. עכשיו יש "מסך בתוך מסך": המשתמש רואה מסך מותאם עם כפתור, לוחץ עליו, ואז נפתח דיאלוג מערכת נוסף. זה גורם לאימות להרגיש כבד יותר ממה שהוא אמור להיות, ולא מנוצל היתרון של Face ID — שהוא אמור להרגיש שקוף ומיידי.

מה אני ממליץ

1. הכי נכון — להסיר את המסך להפעיל את authenticate() ישירות כשה־shouldLock נכון. דיאלוג המערכת הופך לחוויה כולה, ומתחתיו אפשר להשאיר רק רקע דהוי.
2. ביניים — מסך הכנה מותג ולא גנרי לוגו האפליקציה במקום אייקון הפנים, בלי גרדיאנט כחול, בלי כפתור. להריץ את authenticate() אוטומטית ברגע שהמסך מופיע.
3. תיקון מינימלי — fallback וגוון ניטרלי להוסיף כפתור fallback גלוי כמו "התחברות בדרך אחרת", ולהסיר את הגרדיאנט הכחול מהאייקון — להשתמש בגוון הטקסט הרגיל.
