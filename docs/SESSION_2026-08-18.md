## 2. Encryption crashed on device

**Symptom:** saving a coupon failed with
`Native crypto module could not be used to get secure random number.`

**Cause:** `CryptoJS.lib.WordArray.random(16)` generated the Fernet IV. Hermes
exposes no global WebCrypto, so CryptoJS has no random source and throws.

**Fix:** a `randomBytes()` helper that takes the IV from `expo-crypto` on device
and falls back to WebCrypto on web and Node, so the vitest suite still runs.

`src/lib/encryption.ts`

## 3. Scanner

### 3a. One barcode, endless toasts

The re-entry guard was `useState`. `onBarcodeScanned` fires several times per
second and a state update does not land before the next frame's callbacks, so
every one of them saw `scanned === false` and fired its own toast and
`router.push`. The guard is now a `useRef` (synchronous). The 2 s timer that
re-armed it — reopening the camera while the user was already filling in the
form — was replaced with `useFocusEffect`, so the scanner re-arms only when the
user returns to it.

### 3b. The parsed expiry never reached the form

The parser handles Israeli day-first dates correctly; verified against the exact
failing text:

```
"תוקף השובר:\n\n17/08/2031"  →  ["17", "08", "2031"]  →  2031-08-17
```

The value was dropped at the navigation boundary: only `initialCompany`,
`initialCode` and `initialValue` were passed to `/coupons/add`. Added
`initialExpiration` and `initialDescription` on both sides.

### 3c. Reading a voucher from a picture

The camera tab only ever decoded the barcode, i.e. the digits — the amount and
expiry printed beside it were never read, because nothing sent the image
anywhere. Added a photo/gallery path that posts the image to `parse-coupon`
(which forwards it to `gpt-5-mini` as `image_url`).

After feedback, picking an image no longer parses immediately. The image is held
as a removable attachment and one button sends **text and image together** — the
picture carries the layout, the pasted text carries the small print the model
tends to drop.

`src/screens/scanner/BarcodeScannerScreen.tsx`

### 3d. After saving, land on the dashboard

Saving a new coupon called `router.back()`, which returned to the scanner the
user had just finished with. Now `router.replace("/(tabs)")`. Editing still goes
back to wherever it was opened from.

## 4. The app aborted on launch — self-inflicted

`expo-image-picker` was added for §3c and imported at the top of the scanner
screen. Its entry point is:

```ts
// node_modules/expo-image-picker/src/ExponentImagePicker.ts
export default requireNativeModule('ExponentImagePicker');
```

That runs while the module is evaluated and **throws** when the native module is
absent — and `ios/Podfile.lock` had no ExpoImagePicker, i.e. the installed binary
predated the dependency. Metro served the new JS on the old binary, so the
screen took the app down. Crash reports pulled from the device
(`idevicecrashreport`) show expo-updates' deliberate abort:

```
Abort trap: 6 (SIGABRT) — thread: expo.controller.errorRecoveryQueue
  ErrorRecovery.crash()
  ErrorRecovery.runNextTask()
  closure #1 in ErrorRecovery.notify(newRemoteLoadStatus:)
```

**Fix:** `expo-image-picker` is now `require`d lazily inside the handler. The
screen loads on any binary; on a stale one the image buttons show a message
instead of aborting.

> Device logs need `brew install libimobiledevice` (installed this session).
> `idevicesyslog -m CouponMaster` streams the log; `idevicecrashreport -e -k <dir>`
> pulls crash reports. macOS `log stream` has no device option and cannot do this.

## 5. Widget showed zeros

Not a sync failure. `users.allow_widget_access` was `false` on the account, and
`useWidgetSync` treated that as a block — writing an empty payload via
`clearWidgetData()` instead of syncing, with no way to change it from inside the
app.

The column is a nullable leftover from the old product. The widget is for
everyone, so the check was removed; sign-out still clears the payload so coupon
codes do not linger on the home screen. No database row was changed.

`src/hooks/useWidgetSync.ts`

Verified intact while debugging: the app group
`group.com.itaykarkason.couponmaster` matches across
`modules/coupon-widget/ios/CouponWidgetModule.swift`,
`targets/widget/SharedStore.swift`, the app entitlements and
`targets/widget/expo-target.config.js`.
